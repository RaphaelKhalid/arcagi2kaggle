## 6. Perfpatch vs original — conceptual diff

Base for both: the 9-cell "Failed in AIMO" v1. The perfpatch (per its own Chinese-language header and confirmed by line diff) changes **only two hot spots in `arc_solver.py`, algebraically identical outputs**:

1. **`turbo_dfs`:** original did `logits.float().cpu().log_softmax(-1)` — shipping the full ~150k-vocab logits tensor to CPU every DFS step. Patch keeps normalization on GPU (`torch.logsumexp`), `index_select`s only the 12 ARC token logits, and transfers a 12-wide NLL tensor to CPU. Same tokens, same thresholds, same beam ordering.
2. **`calc_scores`:** original ran the scoring forward with `use_cache=True` and moved full log-softmaxed logits to CPU. Patch sets `use_cache=False` (KV cache never consumed in teacher-forced scoring) and gathers only target-token log-probs on GPU.
3. Model path fixed from `/kaggle/input/qwen3_4b_grids15_sft139/...` to `/kaggle/input/models/sorokin/qwen3_4b_grids15_sft139/...` (current mount layout).

Net effect: less CPU-GPU traffic → more tasks finish inside the same 12h budget → higher coverage → 33.89. Time budget, LoRA/TTT config, DFS thresholds, aggregation, and submission schema are untouched.

**Important:** the *current* head of `koushikrudra/failed-in-aimo` (last run 2026-08-03) is no longer the 9-cell v1 — it has grown 3 extra cells implementing the "Leg C" verified-induction pre-pass (Qwen2.5-Coder-7B DSL sampling + sandbox verification + monotonic merge, LEGC_BUDGET_H=1.0, BASE_RESERVE_H=9.8). It does NOT contain the perfpatch GPU optimizations. The obvious uncaptured combination: **perfpatch GPU hot-path + Leg C induction + (optionally) TRM on a staggered GPU** — no public notebook has all three.
